# 301 会议室借用预约小程序（微信云开发版）

一套无需自建服务器的会议室预约小程序，覆盖「查空闲 → 提交申请 → 管理员审批 → 状态同步」完整闭环，适配校内部门、社团借用场景。

- **前端**：微信原生小程序
- **后端**：微信云开发（云数据库 + 云函数），零服务器成本
- **角色**：普通申请人（查空闲、提交、取消、查进度）、管理员（通过 / 驳回）

---

## 一、项目结构说明（先认识每个文件是干什么的）

```
meeting-room-301/
├── miniprogram/                  # 小程序前端代码（用户看到的界面）
│   ├── pages/
│   │   ├── index/                # 首页：会议室信息 + 空闲时段色块看板
│   │   ├── apply/                # 申请页：填写借用表单
│   │   ├── my/                   # 我的申请：查看审批进度、取消申请
│   │   └── admin/                # 审批管理：管理员通过/驳回
│   ├── utils/util.js             # 通用工具函数（日期格式化、校验等）
│   ├── app.js                    # 小程序入口，初始化云开发、静默登录
│   ├── app.json                  # 全局配置（页面路径、底部导航、导航栏）
│   ├── app.wxss                  # 全局样式
│   └── sitemap.json              # 搜索索引配置（默认即可）
├── cloudfunctions/               # 云函数（运行在腾讯云端的后端代码）
│   ├── login/                    # 获取当前用户 openid
│   ├── checkAdmin/               # 判断当前用户是否管理员
│   ├── getRoomSchedule/          # 查询某天已占用时段（不泄露他人隐私）
│   ├── submitReservation/        # 提交申请 + 服务端冲突校验
│   ├── getMyReservations/        # 查询我的全部申请
│   ├── cancelReservation/        # 取消本人待审批申请
│   ├── getAdminList/             # 管理员查询全部申请
│   └── auditReservation/         # 管理员审批（通过/驳回）
├── data-init/                    # 数据库初始化数据模板（照着填）
└── project.config.json           # 开发者工具项目配置
```

> 概念扫盲：**openid** 是每个微信用户在每个小程序里的唯一身份编号，同一个人在不同小程序里 openid 不同，用它来区分「谁提交的申请」。

## 二、准备工作（开始前先装好两样东西）

### 1. 注册小程序账号并拿到 AppID

1. 用电脑浏览器打开 <https://mp.weixin.qq.com/>，点右上角「立即注册」。
2. 账号类型选择 **小程序**，按提示用邮箱注册、完成主体信息登记（个人主体即可，免费）。
3. 登录小程序后台，在左侧菜单「开发 → 开发管理 → 开发设置」里，找到 **AppID(小程序ID)**，复制保存，长这样：`wx1234567890abcdef`。

> 暂时没有 AppID 也可以先在开发者工具里用「测试号」体验，但测试号无法开通正式云开发环境，建议直接注册。

### 2. 下载安装微信开发者工具

打开 <https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html>，下载 **稳定版 Stable Build**（Windows 选 64 位版），双击一路下一步安装即可。

## 三、七步部署流程

### 第 1 步：导入项目

1. 把整个 `meeting-room-301` 文件夹拷贝到电脑上（路径不要含中文、空格，例如 `D:\projects\meeting-room-301`）。
2. 打开微信开发者工具，用微信扫码登录，点击 **「+」新建项目 → 选择「导入项目」**。
3. 目录选择 `meeting-room-301` 文件夹；AppID 填入你自己的 AppID（替换掉配置文件里的占位文字）；后端服务选择 **「微信云开发」**；点击「确定」。
4. 导入后如果提示编译错误，先不用慌，云环境还没配，继续往下走。

### 第 2 步：开通云开发、获取环境 ID

1. 在开发者工具顶部工具栏点击 **「云开发」** 按钮，弹窗中点击「开通」，按提示创建云环境（环境名称随便填，如 `meeting301`；基础版免费额度足够校内使用）。
2. 开通后，在云开发控制台「设置」中能看到 **环境 ID**，形如 `meeting301-9gxxxxxx`，复制它。
3. 打开 `miniprogram/app.js`，找到下面这一行，把环境 ID 粘进去替换占位文字：

```js
envId: 'meeting301-9gxxxxxx' // 替换成你的真实环境 ID
```

4. 保存文件（Ctrl+S），此时控制台关于环境 ID 的警告会消失。

### 第 3 步：创建数据库集合

1. 打开「云开发控制台 → 数据库」，点击 **「+」新建集合**，依次创建 3 个集合，名字必须完全一致：
   - `meeting_rooms`
   - `reservations`
   - `admins`
2. 每个集合创建后，点击集合名 → 「数据权限」（或「权限设置」），按下表配置：

| 集合 | 权限设置 | 原因 |
|------|----------|------|
| `meeting_rooms` | **所有用户可读，仅创建者可写** | 所有人都要看会议室信息 |
| `reservations` | **仅创建者可读写** | 前端不直接操作，全部经云函数（云函数拥有管理端权限，不受此限制） |
| `admins` | **仅管理端可读写**（所有用户不可读写） | 管理员名单属于敏感配置，只能由云函数读取 |

> 若界面上的预设选项与上表文字不完全一致，选择含义最接近的即可；也可以用「自定义安全规则」，对应规则写法见本文档「附录」。

### 第 4 步：部署全部云函数

1. 在开发者工具左侧资源管理器中，找到 `cloudfunctions` 文件夹（图标带云朵）。
2. **逐个右键**点击里面的 8 个云函数文件夹，选择 **「上传并部署：云端安装依赖（不上传 node_modules）」**。
3. 等待每个函数上传完成，文件夹右下角出现小云朵图标即成功；8 个全部要部署：
   `login`、`checkAdmin`、`getRoomSchedule`、`submitReservation`、`getMyReservations`、`cancelReservation`、`getAdminList`、`auditReservation`。

### 第 5 步：获取你自己的 openid（用于设置管理员）

1. 确保 `login` 云函数已部署。
2. 在开发者工具底部点击 **「调试器 / Console」** 标签，在输入框粘贴下面一行后回车：

```js
wx.cloud.callFunction({ name: 'login' }).then(res => console.log('我的openid：', res.result.openid))
```

3. 控制台会打印出你的 openid，形如 `oXx123456789abcdefg`，**完整复制**它。

### 第 6 步：初始化数据（会议室 + 管理员）

**A. 添加 301 会议室**

1. 云开发控制台 → 数据库 → 选中 `meeting_rooms` 集合 → 点击「添加记录」。
2. 按 `data-init/meeting_rooms_示例.json` 的内容逐字段填写（`_id` 不用填，系统自动生成）：
   - `name`：字符串，`301会议室`
   - `location`：字符串，`行政楼3层`（按实际情况改）
   - `capacity`：数字，`50`（注意选 number 类型，不要加引号）
   - `facilities`：字符串，`投影、白板、音响`
   - `enable`：布尔值，`true`
3. 保存。

**B. 添加管理员**

1. 选中 `admins` 集合 →「添加记录」，参照 `data-init/admins_示例.json`：
   - `openid`：字符串，粘贴第 5 步拿到的**你自己的 openid**
   - `name`：字符串，你的姓名
   - `role`：字符串，如 `办公室部长`
2. 保存。以后要加更多管理员，照此格式再添加一条即可。

> `reservations` 集合**不需要手动添加任何数据**，用户提交申请时会自动生成。

### 第 7 步：编译验证

1. 点击开发者工具顶部的「编译」按钮，模拟器中应能看到首页：301 会议室卡片、日期、8:00-22:00 的时段网格（全绿表示空闲）。
2. 底部有「预约首页 / 我的申请 / 审批管理」三个标签。

建议用两个微信号测试：一个当管理员，一个当普通同学（可在开发者工具「预览」用手机扫码，或用「真机调试」）。

|------|----------|----------|
| 1 | 首页切换今天/明天/后天、选择日期 | 时段色块正常刷新 |

## 五、提交审核上线

1. 测试全部通过后，点击开发者工具顶部「上传」，填写版本号（如 `1.0.0`）和备注，上传代码。
2. 登录小程序后台 <https://mp.weixin.qq.com/>，进入「管理 → 版本管理」，在「开发版本」中找到刚上传的版本，点击 **「提交审核」**，按要求填写功能页面、类目（可选「工具 → 办公」相关类目）。
3. 审核通过后（一般几个小时到 1～2 天），回到版本管理点击「发布」，全校同学即可搜索使用。
4. 发布前需在后台「设置 → 用户隐私保护指引」中声明收集的信息（手机号、微信账号等），按页面提示勾选用途即可。

## 六、常见问题排查（零基础高频报错）

**1. 控制台报「请先填写云开发环境 ID」或 `env identifier invalid`**
→ `app.js` 里的 `envId` 没改或填错，回到第 2 步重新复制环境 ID，注意不要带空格。

**2. 调用云函数报 `FunctionName` 不存在 / `-404011`**
→ 对应云函数没部署或名字拼错。右键该云函数文件夹重新「上传并部署」，确认云端函数名与代码里 `callFunction({ name: 'xxx' })` 完全一致。

**3. 云函数报 `Cannot find module 'wx-server-sdk'`**
→ 部署时选了「不上传依赖」但云端没装依赖。重新右键选择「上传并部署：云端安装依赖」。

**4. 首页一直转圈 / 读不到会议室信息**
→ 检查 `meeting_rooms` 集合是否已添加记录、`name` 是否恰好为 `301会议室`、数据权限是否为「所有用户可读」。

**5. 我明明是管理员，审批页却显示无权限**
→ 99% 是 `admins` 里的 openid 填错了。重新执行第 5 步打印 openid，与数据库里的逐字符比对（注意首尾不要有空格），修改后重新编译。

**6. 数据库里时间字段看不懂（一串 13 位数字）**
→ 那是毫秒级时间戳，属正常存储方式；界面上已通过 `util.js` 转成 `HH:MM` 显示，无需手动改。

**7. 非管理员能直接改数据库吗？**
→ 不能。所有写操作都在云函数内完成并带身份校验，前端无法绕过；`admins` 集合对普通用户完全不可读。

**8. 免费额度够用吗？会收费吗？**
→ 云开发基础版含一定次数的云函数调用、数据库读写和存储，校内单会议室场景通常远低于上限；后续用量大了可在控制台按需升级。

## 七、进阶优化方向（当前版本已预留扩展空间）

1. **订阅消息通知**：审批结果通过微信订阅消息实时推送给申请人，免去主动查询。
2. **多会议室扩展**：`meeting_rooms` 已支持多条记录，首页加会议室选择器即可管理整栋楼。
3. **签到核销**：预约当日现场扫码签到，超时未到自动释放时段。
4. **周期预约**：支持每周固定时段重复借用，一次申请自动生成多条记录。
5. **数据统计**：按月导出借用记录，统计会议室使用率、部门活跃度。
6. **黑名单机制**：对多次爽约用户限制预约资格。

## 附录：数据库自定义安全规则写法

如果使用「自定义安全规则」，三个集合分别粘贴：

`meeting_rooms`（所有人可读，无人能从前端直接写）：

```json
{
  "read": true,
  "write": false
}
```

`reservations`（仅文档创建者本人可读写；创建者以 openid 字段为准）：

```json
{
  "read": "doc.applicantOpenid == auth.openid",
  "write": "doc.applicantOpenid == auth.openid"
}
```

`admins`（前端完全不可读写，仅云函数可访问）：

```json
{
  "read": false,
  "write": false
}
```

> 云函数通过 `wx-server-sdk` 操作数据库时使用管理端权限，以上规则不会影响云函数的正常读写。
